AnSci / Root — System Schematic

Preview of the reorganised root page: the codebase redrawn as one zoomable schematic. What is drawn here is a general-purpose system — not a chat system. Chat is a configuration applied to it, its first configuration, shown on the System frame. Zoom in and the boxes open up — the System contains the LPU, the LPU contains the Parser, and the Parser contains its submodules; around them sit Awareness, Session & Situation, Knowledge, Reasoning, and Intake & Harboring. Nesting means containment only: a resource is reached by a connection cord labelled uses — as the Verbalizer uses the LPU — while pathway cords (double tracks) carry the travelling circle. Hierarchy is read from gradations of gray, deeper elements on stronger grounds. Press Trace “Hello” and watch a single utterance travel the whole machine, under the Chat configuration.

    Inspector

    The System
    System
    The outermost bounding box and the new root page's whole subject. Everything else on this schematic is inside it. Its IN port takes a person's utterance; its OUT port delivers the reply.
    IN — utteranceOUT — reply

    Legend — module types

    One drafting family — same rectangles, same stroke, same title placement. Type is carried by small systematic treatments only: a corner, an edge, a ruling. Held modules are double-ruled, active modules single-ruled; containers are double-ruled frames with a title tab.

    UNIT
    Transforms: in → work → out. Told by a chamfered output corner. Parser, Generator, Planner.
    STORE
    Holds and is consulted; never acts. Told by a double bottom edge — a shelf line. Knowledge graph, lexicon.
    REGISTER
    Holds current state — small, rewritten constantly. Told by a segmented top strip. Session record, situation statement.
    TABLE
    Fixed mapping: key in → value out; never changes at runtime. Told by faint internal ruling. Pricing ceilings, correspondence tables, composition definitions.
    GATE
    Stands in a path and prices or refuses passage. Told by a bold input edge — a barrier line. Harbor gate, decline floor, confidence band.
    ROUTER
    Directs flow among paths, by rule. Told by the only rounded corners on the map. The Intake Router: local graph → CSKG → Wikidata → web → model.
    SOURCE
    Originates input from outside the boundary. Told by placement alone — astride the System boundary. Clock, the person's channel, external tiers.
    SURFACE
    Where output leaves and is seen. Told by a double top edge. Reply surface, dashboard, trace view.

    Cords — connection vs pathway

    PATHWAY CORD
    Two close parallel hairlines — a track. A token — the circle — can travel it. These form the utterance circuit. A Store never has one; a Gate sits astride one.
    CONNECTION CORD
    One hairline, open dot at the end that is read. Standing structure, labelled with its verb: consults · holds · writes · uses.
    TAKEN PATH
    Not a third cord — a state. As the circle travels, the pathway behind it fills to one solid weight, so a finished trace leaves the actual journey standing among the merely possible ones.

    Containment vs use

    A box inside a box means containment — nothing else. A module that is a resource for another is never nested inside its user: it is reached by a connection cord labelled uses. The Verbalizer is the standing example — a System-level element whose uses cord runs to the Generator inside the LPU it makes use of.

    Gray hierarchy

    SystemSectionUnitSubmodule

    Hierarchy is carried by gradations of gray: the deeper an element sits, the stronger its ground. Colour is reserved for the travelling circle and the path it takes.

    Zoom is the organising idea of the reorganisation: at System zoom you see the units; at Parser zoom you see four submodules. The root page will work the same way — one map, every scale.
