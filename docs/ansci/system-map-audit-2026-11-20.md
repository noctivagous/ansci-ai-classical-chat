# System-Map Audit — AnSci

**Date:** 2026-11-20 · **Commit audited:** `546293d` ("Add per-node system map audit procedure and ledger")
**Procedure:** GAPS.md "Diagnosis and design discipline" + "System-map audit procedure and progress" (2026-11-20) — the 7 steps: resolve the claim, classify implementation, check wiring, check tests and behaviour, diagnose at the earliest supported divergence, assess design fit, record disposition.
**Method:** six parallel batch audits (A–F), each node resolved against `ai-system/system-map.ts` and its named source files (opened, not filename-trusted), callers traced by grep from the chat entry point (`scripts/ansci-chat.mjs` → `processTurn`, `src/ansci/turn.ts`), tests/fixtures/scripts grepped per node. No batch ran builds or tests; no behaviour was fabricated. Batch evidence that was thin is marked `needs-evaluation` rather than polished.

## Baseline (established before the batches; cited, not re-run per node)

- `npm run build` (tsc) clean.
- `npm run ai:check` passes: 106 nodes, 86 directories, 22 cords, layout covers 106 nodes; root page carries all 103 percented nodes (3 externals carry no percent). This checks registry/layout correspondence only — not functional coverage.
- `npm run ansci:audit`: 2 pass, 1 known gap (`opening-event-is-not-yet-receipted` — an opening statement hidden behind a bare acknowledgement, no record receipt), 0 unexpected failures.
- Ledger IDs in GAPS.md match map IDs exactly (106 = 106).

## Findings — every gap located, in plain register

What was checked: all 106 map entries resolved against their named source files (opened, not filename-trusted); callers traced from the chat entry point through `processTurn`; tests, fixtures and scripts grepped per node; the baseline (`build` clean, `ai:check` pass, behaviour audit 2 pass / 1 known gap) cited as the only behaviour actually run. What this audit does **not** show: usefulness in conversation beyond the narrow tested scopes — the behaviour fixture has only 3 cases; no held-out or unseen cases were examined; no DOM/layout measurement or live render was performed; no live source (Wikidata, weather.gov, host clock) was exercised against the network. Nobody independent has checked these findings. Every node except `unplaced` and `person` is therefore audited-open.

**The reachability pattern (the audit's main finding)**
1. **Built, tested, and unreachable in ordinary conversation** — the same shape at many addresses: Valency's `assessValency` (no caller in `src/`); Monitoring's wrapper (no caller in any script/demo; no conversational registration route); Wikidata live lookup (only inside `processTurnWithWikidata`, which the default chat does not use); CSKG retrieval (acquisition built, no turn ever consults it); the host-clock route (no shell passes a `clockSource`); the live weather feed (fetch lives in an async wrapper no shell calls — surface weather questions end at the `lookup-needed` decline); Calendar and Timeline (working libraries `turn.ts` does not import); Scheduling's and Expectation's weather consumers (wrapper-only); `edu-reach`'s counteraction walk (no caller); the Luoshu apparatus and ch.4 number readings (annotation only, no caller); ParamorphicConcept's registry (no caller); UnitsMeasurement `convert()` (one Form-programme probe); `flavor-bridge` derived correspondences (by its own header, nothing reads it); `listOpenUnknowns`/`listSurvivingNeeds` (tested views, no turn-path reader — found independently by Batches A and C); ProblemSolving's `openProblem`/`moveAlongStandingRoute`/`auditCapability` (tests only).
