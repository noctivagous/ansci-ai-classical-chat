# FND-201 — clock and live-chat configuration parity: record 2026-11-22

## Entry-point matrix (read from code, then probed)

| path | session | clockSource | frame | interlocutor store |
|---|---|---|---|---|
| Foundry run/evaluate | `newSession()` | none | none | none |
| Terminal `ansci-chat.mjs` | `newSession(undefined, undefined, {store: File})` | none | none | file-backed (`~/.ansci/interlocutors.json` or `ANSCI_INTERLOCUTOR_STORE`) |
| Dashboard `engine-entry.ts` (AnSciLive) | `newSession()` | none | none | none |
| Dashboard chat `App.tsx` | `newSession(NEUTRAL_COMPOSITION, frameFromClock())` | none | browser-clock hour/month/day | none |

No live path wires a `clockSource`. Time/date answers come from the
frame when one stands (Probe-2 Slice 5) or from a wired clock
(Timekeeping T1); otherwise the turn declines, located at the missing
reading.

## Measured behavior (current tree, in-process probes)

- "What is the time?": no clock/frame → located decline ("no clock
  reading"); frame hour 15 → "It is about 3 PM."; fixture clock
  15:04 UTC → "It is 3:04 PM.", identical on repeat — the control
  works and is deterministic.
- "What is the date?" / "What is the date today?": frame with
  month/day → "The date is November 22." / with fixture clock "The
  date is November 22, 2026."; plain → located decline. (Note: "What
  time is it?" takes a different parse route and never reaches the
  clock shape in any config — the routed phrasing is "What is the
  time?".)
- Terminal store vs Foundry: within one session, identical. Across
  sessions sharing one store file, a new session still answers "You
  have not told me your name" until the identity is stated again
  (the store's own rule, per the chat runner's comment) — so the
  store changes cross-run behavior only on re-statement, and
  Foundry's in-memory sessions never persist at all.
- Browser live run: not executed (Vite app + async lexical load);
  App.tsx configuration is code-read evidence above, live parity
  unverified.

## What this settles, and what remains (FND-200)

Settled: the four configurations are enumerated with sources; the
fixture control is demonstrated deterministic; the store difference
is measured; every Foundry report to date (unpinned clock, no frame)
is comparable with every other, and time-sensitive cases would
decline identically rather than differ silently. Remaining for
FND-200: wall-clock reads outside the turn's clock route (weather
bank freshness per turn, geography registers) still default to live
time, and no path wires `HostClockSource` by default — pinning those
is the rest of the reproducibility program.
