# FND-103 — implement comparable before/after reports: record 2026-11-22

Implemented `compare --before <report> --after <report> --json`.

## What changed

- `src/ansci/foundry-compare.ts` (new): pure `compareReports`,
  `compareCases`, `compareConfigurations`. Identity is by case, turn and
  check ID. Check transitions: pass→fail regression, fail→pass gain,
  anything involving abstained/not-observable is evidence-changed, never
  a silent gain or regression. Case verdicts: gain, regression,
  still-failing, unexpected-pass (a fixed known-failure — flagged for
  suite review, not counted as a plain gain), only-before/only-after,
  suite-changed (mixed transitions or changed check/turn sets). Fixture
  digests and flattened configuration differences are reported
  explicitly; reply-only wording changes are noted without grading.
- `scripts/ansci-foundry.mjs`: compare branch. No resources or turn path
  needed, so no resource verification. Exit 0 when comparable cases show
  no regressions and no unexpected passes; exit 1 on regressions or
  needs-review; exit 2 on invalid reports, bad arity, or zero comparable
  cases (wrong pair, not a clean bill of health).
- `test/ansci-foundry-compare.test.ts` (new, 6 tests, registered in t3):
  identical, regression, gain, incomparable, fixture/config reporting,
  unexpected-pass flagging. 12/12 with the evaluate tests.
- `loop/FOUNDRY.md`: all three commands now recorded implemented.

## Limits

Reply wording is compared for change only, never graded. A reformatted
suite file changes the fixture digest and raises `suiteChanged` even
when case IDs are identical — visible, by design. Direct
`node scripts/ansci-foundry.mjs` invocation still required given the
pre-existing physics/planck build short-circuit (see FND-102 record).
