# FND-200 — reproducible runtime settings: record 2026-11-22

## What was pinned

1. Foundry fixture clock. Suites may declare
   `configuration.clock.fixture.{instant, timezone, name}`; the runner
   (`src/ansci/foundry-clock.ts`, unit-tested, rejects anything else
   with exit 2) wires a `FixtureClockSource` into every fresh session,
   and the report records the pinning instead of "not pinned".
2. The turn path's remaining wall-clock read. Weather-bank freshness
   was stamped with `new Date()` per turn; it now reads the session
   clock when one is wired (`sessionNowISO`), host clock otherwise —
   no behavior change unless a clock is wired. Audit result: this was
   the only `Date`/`now` read reachable from `processTurn`;
   geography-turn's `now` defaults sit outside the turn path (it wraps
   the turn loop, not vice versa) and were left alone.
3. Proof suite. `loop/foundry-cases/english-time.json` pins
   2026-11-22T15:04:00Z and asserts the time/date answers. Two runs
   are byte-identical modulo run metadata; `compare` reports
   2/2 unchanged, exit 0.

## Evidence

- `test/ansci-foundry-clock.test.ts` (3 tests, in t3): absent config,
  pinning/determinism, malformed rejection.
- Pinned runs exit 0; dev suite still 12/12 pass on the same tree
  (clock absent → behavior unchanged).
- Entry-point differences remain as measured in FND-201 (no live path
  wires a clock by default; frame only in the dashboard chat tab;
  store terminal-only; browser live run unverified) — documented,
  not silently equated.

## Deliberately unchanged

Live defaults: terminal, dashboard and Foundry sessions still open
with no clock, so their declines are unchanged. Wiring `HostClockSource`
by default would change live replies and is a product decision, not a
reproducibility fix. Geography register defaults are injectable and
outside the turn path.
